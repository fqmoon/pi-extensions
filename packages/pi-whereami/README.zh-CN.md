# pi-whereami

[English](README.md) | 简体中文

## Agent 还在忙，但它现在走到哪了？

任务一长，Agent 可能连续读文件、追调用链、不断调用工具。你看得见它在做事，却越来越难看清：它已经搞明白了什么？下一步还在解决原来的问题吗？

`pi-whereami` 会定期提醒**正在执行任务的 Agent**，先重新确认一下自己的位置：

- 我现在在哪个层级、哪个范围里工作？
- 目前的判断是什么？
- 这条路还值得继续，还是只是在顺着惯性往下走？
- 接下来最有用的一步是什么？

Agent 留下一条简短的位置记录，然后继续原任务。你可以在输入框上方看到它最近一次记录的位置，也可以在对话历史里回看之前的记录。

**不用另开一个监督 Agent，也不用你反复追问“现在到哪了？”**

## 安装

需要 **Pi 0.87.1 或更新版本**。

```bash
pi install npm:pi-whereami
```

启动 Pi；如果已经在会话中，执行 `/reload`。之后照常给 Agent 布置任务即可，不需要额外命令或配置。

也可以在本仓库根目录直接加载，先试用一下：

```bash
pi -e ./packages/pi-whereami/index.ts
```

## 装上后会看到什么

Agent 开始工作后，输入框上方会出现一个小面板。例如：

```text
whereami · Decisions: 13/20 · Checkpoints: 1 · Latest checkpoint
Level: module · Scope: 渲染管线
State: 目前仍怀疑是失效标记没有正确传播
Next: 检查脏标记的传播边界
```

四个字段分别表示：

| 字段 | 含义 |
| --- | --- |
| Level | 当前工作的细节层级，例如子系统、模块或函数。 |
| Scope | 当前聚焦的问题范围。 |
| State | 目前的认识或判断，不是推理过程的复述。 |
| Next | 接下来准备采取的关键行动。 |

`Decisions: 13/20` 表示：从你上一条消息开始，Agent 已完成 13 次主任务回复，下一次检查预计在第 20 次触发。它**不是任务完成百分比**。`Checkpoints: 1` 表示这段时间里成功记录了 1 条检查点。

还没有记录时，面板显示 `Awaiting first checkpoint`；正在收集时，显示 `Updating checkpoint`。只有收到有效检查点，位置字段才会更新：**它是定期快照，不是实时工具活动列表**。

Agent 完成任务或被中断后，面板仍会保留。你发送下一条消息时，面板会重新开始；旧记录仍留在对话历史里。恢复会话或切换分支后，开始执行时会显示对应的位置。

面板标签目前固定为英文，上面的示例没有翻译这些标签。非交互模式也会记录检查点，但不显示面板。

## 多久检查一次

每条新用户消息之后，先等 Agent 完成 **12 次主任务模型回复**，再进行第一次检查。后续间隔依次是 **8 次、6 次、4 次**，之后保持每 4 次检查一次。

一次回复只计一次，无论其中调用了一个工具，还是并行调用了多个工具。这里数的是模型回复轮次，不是工具调用数，也不是经过了多少时间。专门用于记录检查点的回复，不会计入下一次间隔。

检查会等当前这批任务工具执行完，并优先处理你等待中的输入。插件不会为了补一条记录，重新启动已经结束的任务，所以短任务可能没有检查点。

## 它能做什么，不能保证什么

默认提醒会让 Agent 重新审视自己的工作层级、主要疑问和证据来源。如果换一条路更有助于解决问题，就考虑换路；如果当前的深入调查仍然有效，就继续。

**插件负责提醒 Agent 重新判断，不负责替它判定对错。**

- 不会独立检测跑偏、验证进展，也不会强制改变方向。
- 检查点是 Agent 对当前位置的描述，不代表某个里程碑已经完成。
- 使用当前 Agent 和模型，不需要另配审核模型或 API Key；但检查可能增加模型调用轮次、Token 消耗和等待时间。
- 检查点保存在会话中，也会进入后续模型上下文。Pi 自动压缩上下文时，较早的记录可能被概括。
- 如果 Agent 没有给出有效检查点，就跳过这次记录，继续工作；面板保留最近一次有效位置（如果已有）。

它适合长时间调查或实现任务中的偶尔回看与定位，不是逐步监督 Agent 的另一套系统。

## 可选：换成你自己的提醒

默认提醒不需要任何配置。如果想替换它，可以创建：

```text
~/.pi/agent/whereami/reorient.md
```

例如：

```markdown
继续之前，检查最近的工作有没有缩小主要疑问。
如果没有，考虑一个竞争解释，或换一种证据来源。
如果调查仍然有效，就保持方向，不要为了换路而换路。
```

文件内容会**替换**默认的重新定位提醒。你不需要规定检查点格式：插件仍会要求 Agent 填写四个字段，然后继续原任务。

修改后执行 `/reload`。文件不存在、为空或无法读取时，会使用默认提醒。如果设置了 `PI_CODING_AGENT_DIR`，文件应放在该目录下的 `whereami/reorient.md`。目前没有项目级提醒文件，也没有检查间隔设置。
